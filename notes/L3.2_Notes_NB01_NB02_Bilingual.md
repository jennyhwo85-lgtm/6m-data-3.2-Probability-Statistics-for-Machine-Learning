## Cell 3 — Recreate the Data (Synthetic)
*Cell 3——重建数据（人为生成）*

```python
positive = np.random.exponential(scale=0.35, size=6_000)
positive = np.clip(positive, 0.001, 1.0)

negative = -np.random.exponential(scale=0.20, size=4_000)
negative = np.clip(negative, -1.0, -0.001)

np.random.shuffle(polarity_scores)
```

| Code / 代码 | Meaning / 意思 |
|---|---|
| **Polarity score**<br>*情感极性分数* | From −1 (very negative) to +1 (very positive)<br>*−1（非常负面）到 +1（非常正面）* |
| `exponential(scale=0.35)`<br>*指数分布* | Most values small, a few large → **right-skewed**<br>*大部分值小，少数值大 → **右偏*** |
| `size=6_000 / 4_000` | 6,000 positive + 4,000 negative are set by hand, so exactly 60%<br>*人为设定 6,000 正面 + 4,000 负面，所以正好 60%* |
| `np.clip(x, 0.001, 1.0)` | Caps the values: anything above 1.0 becomes 1.0 (**important later**)<br>*设上下限：超过 1.0 的一律变成 1.0（**后面很重要**）* |
| Negative `scale=0.20`<br>*负面 `scale=0.20`* | Smaller than positive → negative reviews cluster near 0<br>*比正面更小 → 负面评论集中在 0 附近* |

### Code techniques
*代码技巧*

**① The median is written differently in numpy**

*① numpy 的中位数写法不同*

```python
polarity_scores.mean()        # method on the array / 数组自带的方法
polarity_scores.std()         # method on the array / 数组自带的方法
np.median(polarity_scores)    # numpy arrays have no .median() / numpy 数组没有 .median()
# pandas Series can use: df['col'].median() / pandas 可以直接写 df['col'].median()
```

**② f-string formatting**

*② f-string 格式化*

| Syntax / 写法 | Meaning / 意思 | Example / 例子 | Excel |
|---|---|---|---|
| `{x:.4f}` | 4 decimals<br>*4 位小数* | 0.1206 | `0.0000` |
| `{x:,}` | Thousands separator<br>*千分位* | 6,000 | `#,##0` |
| `{x:.1%}` | Percent, 1 decimal<br>*百分比 1 位小数* | 60.0% | `0.0%` |

**③ ⭐ Boolean mask: the most important technique**

*③ ⭐ 布尔掩码：最重要的技巧*

```python
(polarity_scores > 0).sum()    # 6,000 → count / 计数
(polarity_scores > 0).mean()   # 0.600 → proportion / 比例
```

- `> 0` produces 10,000 True / False values.

  *`> 0` 会产生 10,000 个 True / False。*
- True = 1, False = 0.

  *True = 1，False = 0。*
- `.sum()` = count; `.mean()` = proportion.

  *`.sum()` = 个数；`.mean()` = 比例。*

> 💡 **Excel analogy:** `.sum()` = `COUNTIF(A:A, ">0")`; `.mean()` = `COUNTIF(A:A, ">0") / COUNT(A:A)`.
>
> *💡 **Excel 类比**：`.sum()` = `COUNTIF(A:A, ">0")`；`.mean()` = `COUNTIF(A:A, ">0") / COUNT(A:A)`。*
>
> This "`.mean()` for a proportion" trick is used again for accuracy (NB03) and repurchase rate (NB04).
>
> *这个"用 `.mean()` 算比例"的写法在 NB03（准确率）和 NB04（复购率）会一直用到。*

### 🆕 Skewness
*🆕 偏度*

```python
reviews_df['polarity'].skew()     # 0.466
reviews_df['word_count'].skew()   # 1.993
```

| Skew | Meaning / 意思 |
|---|---|
| 0 | Perfectly symmetric<br>*完全对称* |
| > 0 | Right-skewed (long tail on the right)<br>*右偏（长尾在右）* |
| < 0 | Left-skewed (long tail on the left)<br>*左偏（长尾在左）* |

| \|Skew\| | Degree (rule of thumb) / 程度（经验法则） |
|---|---|
| < 0.5 | Roughly symmetric / mild<br>*大致对称 / 轻度偏* |
| 0.5 – 1 | Moderate<br>*中度偏* |
| > 1 | **Highly skewed**<br>***高度偏*** |

- **Polarity 0.466:** mildly right-skewed (at the edge of "symmetric").

  ***Polarity 0.466**：轻度右偏（接近对称的边界）。*
- **Word count 1.993:** **highly right-skewed**, about 4× polarity's skew.

  ***Word count 1.993**：**高度右偏**，约是 polarity 的 4 倍。*

**How it is calculated (intuition):** turn each value into a Z-score → **cube it** → take the average.

*计算直觉：把每个值转成 Z 分数 → **取三次方** → 求平均。*
- Cubing **keeps the sign**: extreme values on the right become large positives, on the left large negatives.

  *三次方**保留正负号**：右边的极端值变成大正数，左边的变成大负数。*
- Cubing **amplifies extremes**: Z = 3 → 27, while Z = 1 → 1.

  *三次方**放大极端值**：Z = 3 → 27，而 Z = 1 → 1。*

> 💡 **Accounting analogy:** one huge invoice in a set of expenses affects the total far more than many small ones. Skewness puts a number on the influence of the extremes.
>
> *💡 **会计类比**：一组费用里有一张巨额发票，它对总额的影响远大于小额发票。偏度就是把"极端值的影响"量化出来。*

| Right-skewed<br>*右偏* | Long right tail, mean > median<br>*右侧长尾，均值 > 中位数* | Incomes, review lengths, house prices<br>*收入、评论长度、房价* |
| Left-skewed<br>*左偏* | Long left tail, mean < median<br>*左侧长尾，均值 < 中位数* | Easy exam scores, age at retirement<br>*简单考试分数、退休年龄* |
| Mean vs Median<br>*均值 vs 中位数* | Mean is pulled by extremes; median is not<br>*均值受极端值影响，中位数不受* | Check both when data may be skewed<br>*可能偏态时两个都要看* |

**Reporting rule:**

*报告规则：*
- Symmetric → quote either mean or median.

  *对称 → 均值或中位数都可以。*
- Skewed → use the **median** for the "**typical**" value; use the **mean** for "**totals**".

  *偏态 → "**典型值**"用**中位数**；"**总量**"用**均值**。*

## Cell A — Compute Z-scores ✅ Run
*Cell A——计算 Z 分数 ✅ 已运行*

```python
pol_mean = polarity_scores.mean()   # 0.1206
pol_std  = polarity_scores.std()    # 0.3564

reviews_df['z_score'] = (reviews_df['polarity'] - pol_mean) / pol_std
```

- **Formula:** `z = (value − mean) / standard deviation`

  ***公式**：`z = (数值 − 均值) / 标准差`*
- This one line computes all 10,000 values at once: a **vectorised operation**.

  *这一行对 10,000 个数同时计算，叫**向量化运算**。*
- 💡 **Excel analogy:** type `=(B2-$B$10002)/$B$10003` in a new column and fill down 10,000 rows.

  *💡 **Excel 类比**：在新的一列写 `=(B2-$B$10002)/$B$10003`，然后往下拉 10,000 行。*

| Code / 代码 | Purpose / 作用 | Excel |

| `nlargest(3, 'z_score')` | 3 rows with the largest Z<br>*Z 最大的 3 行* | `LARGE()` |
| `nsmallest(3, 'z_score')` | 3 rows with the smallest Z<br>*Z 最小的 3 行* | `SMALL()` |
| `[['polarity','z_score','label']]` | Show only these 3 columns<br>*只显示这 3 列* | Hide other columns<br>*隐藏其他列* |
| `.to_string(index=False)` | Print without row numbers<br>*打印时不显示行号* | |

### Z-score example (from the slides)
*Z 分数例子（PPT）*

| Scenario / 情境 | Calculation / 计算 | Meaning / 含义 |
|---|---|---|
| Score 85; class avg 60, std 10<br>*考 85 分；班均 60，标准差 10* | z = (85−60)/10 = **2.5** | Top ~1% of the class<br>*全班前约 1%* |
| Score 85; class avg 82, std 2<br>*考 85 分；班均 82，标准差 2* | z = (85−82)/2 = **1.5** | Above average, not exceptional<br>*高于平均，但不突出* |

→ **The same raw score means very different things in different contexts.**

*→ **同样的 85 分，在不同语境下意义完全不同。***

## 🔍 Key question: why is the highest positive Z only +2.467?
*🔍 关键：为什么正面最高只有 +2.467？*

```
Highest score +1.0:  Z = (1.0 − 0.1206) / 0.3564  = +2.467
Lowest score  −1.0:  Z = (−1.0 − 0.1206) / 0.3564 = −3.144
```

Now work backwards: **what polarity would Z = ±3 need?**

*反过来算：**Z = ±3 对应的极性分数是多少？***

```
Z = +3  →  polarity = 0.1206 + 3 × 0.3564 = +1.19   ← above the 1.0 cap: impossible! / 超过上限，不可能出现！
Z = −3  →  polarity = 0.1206 − 3 × 0.3564 = −0.949  ← possible / 可以出现
```

**Conclusion:** however enthusiastic a review is, its Z can **never exceed +3**. The "|Z| > 3" rule is **mathematically lopsided** on this data.

*结论：不管评论多热情，Z **永远不可能超过 +3**。"|Z| > 3" 规则在这份数据上**数学上就是不对称的**。*

## ✅ The better approach: the IQR method
*✅ 正确做法：IQR 方法*

```
IQR         = Q3 − Q1
Lower fence = Q1 − 1.5 × IQR     (下界)
Upper fence = Q3 + 1.5 × IQR     (上界)
```

Using the `describe()` numbers:

*用 `describe()` 的数字：*

```
Q1 = −0.092    Q3 = 0.306    IQR = 0.398
Lower = −0.092 − 1.5 × 0.398 = −0.689
Upper =  0.306 + 1.5 × 0.398 = +0.903
```

| Method / 方法 | Negative outliers / 负面离群值 | Positive outliers / 正面离群值 |
|---|---|---|
| Z-score (\|Z\| > 3) | 27 | **0** ❌ |
| IQR (1.5 × IQR) | 97 | **466** ✅ |

IQR uses **quartiles**, not the mean and std, so it is **not distorted by skew or extreme values**. This is the same reason we use the median for skewed data.

*IQR 用的是**四分位数**，不依赖均值和标准差，所以**不受偏态和极端值影响**。这和"偏态数据用中位数"是同一个道理。*

```python
# IQR code (try it yourself) / IQR 代码（自己可以试）
q1, q3 = np.percentile(polarity_scores, [25, 75])
iqr = q3 - q1
lower, upper = q1 - 1.5 * iqr, q3 + 1.5 * iqr
n_low  = (polarity_scores < lower).sum()   # 97
n_high = (polarity_scores > upper).sum()   # 466
```

> 💡 **Audit analogy:** flagging transactions beyond "mean ± 3 std" misses one side if amounts are heavily skewed (mostly small, a few huge). IQR works more like stratifying by percentiles: robust whatever the data's shape.
>
> *💡 **审计类比**：用"平均值 ± 3 个标准差"抽查异常交易时，如果金额严重偏态（大部分小额，少数巨额），会漏掉一边。IQR 更像按分位数分层：不管数据形状如何都比较稳健。*

### When can you use Z-scores?
*Z 分数什么时候可以用？*

| Use / 用途 | OK? / 适用？ |
|---|---|
| **Feature standardisation** (ML preprocessing)<br>***特征标准化**（机器学习预处理）* | ✅ Any distribution<br>*✅ 任何分布都可以* |
| **Outlier detection** (\|Z\| > 3)<br>***离群值检测*** | ⚠️ **Only for roughly normal data**<br>*⚠️ **只适合近似正态的数据*** |

**Key takeaway:** check the distribution shape *before* choosing an outlier method.

*核心：先看分布形状，**再**选离群值检测方法。*

# Key Takeaways
*核心要点*

1. **One number is never the whole story.** Look at the distribution behind it.

   ***一个数字永远不是全部**：先看背后的分布。*
2. **"60% positive" depends on the threshold:** 0 → 60%, 0.1 → 45%, 0.3 → 26%.

   ***"60% 正面"取决于阈值定义**：0 → 60%，0.1 → 45%，0.3 → 26%。*
3. **Mean > Median → right-skewed.** For skewed data, use the **median** as the "typical" value.

   ***均值 > 中位数 → 右偏**；偏态数据的"典型值"用**中位数**。*
4. **In `describe()`, 50% is the median**; 25% / 75% are Q1 / Q3.

   ***`describe()` 的 50% 就是中位数**；25% / 75% 是 Q1 / Q3。*
5. **|Skew| > 1 means highly skewed.**

   ***|偏度| > 1 = 高度偏。***
6. **Z-scores are fine for standardisation**, but the **|Z| > 3 outlier rule only suits roughly normal data**.

   ***Z 分数适合做标准化**，但 **|Z| > 3 离群值规则只适合近似正态的数据**。*
7. **Skewed or capped data → use IQR for outliers.**

   ***偏态或有封顶的数据 → 用 IQR 找离群值。***
8. **Clipping / caps create illusions** (ceiling effect). Know whether your data has limits before interpreting results.

   ***封顶会制造假象**（天花板效应）。解读结果前要知道数据有没有上下限。*
